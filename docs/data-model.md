# Data model (Firestore)

Source: spec Section 11. Security rules: `firebase/firestore.rules` (T-FND-06, human review required).
Database: Standard `(default)` in nam5 per project (D-16). Every document carries `created_at`, `updated_at`, `schema_version`.
App code gets Firestore only through `firestoreProvider` (D-16).

## Cloud Storage (D-76)

Rules: `firebase/storage.rules`, nothing open to clients (the server uses the Admin SDK and signed URLs). Reserved prefixes for personal media; revoke handling deletes them:

| Prefix | Holds | Deleted when revoked |
|---|---|---|
| `selfies/{uid}/` | raw selfie photos/video (16.3: 7 days max; the Media Service keeps selfies in memory only today) | camera, biometric |
| `avatars/{uid}/` | approved portraits (`portraits/`) and frame sets (`{version}/`) (D-64, T-AVT-08d) | camera, biometric |
| `voice_samples/{uid}/` | raw voice samples and raw consent audio (16.3) | microphone, biometric |
| `exports/{uid}/{jobId}.zip` | data export zips (T-CMP-03, D-82), downloaded only through a short-lived signed link; deleted after 7 days by the bucket's lifecycle rule (`firebase/storage-lifecycle.json`) | — (the person's own copy) |

Anything not listed is denied.

**Data export (FR-SET-02, D-82).** Every collection above is either exported or excluded with a reason in `services/core-api/src/account/export-collections.ts`; a test reads this table and fails when a new collection isn't classified there. Add a new collection to that file in the same change.

**Migrations.** T-PRT-02 (D-92): none. Nothing in the repo wrote `portal_offers` before, the fields the app reads are unchanged, and the new fields and `portal_offer_workflow` start at `schema_version: 1`. An offer added by hand in the Firebase console still loads in the app and shows in the Admin (no workflow document = rev 1, no editors).
